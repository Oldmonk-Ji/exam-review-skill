# PDF 交付工作流

仅在选定 PDF 时执行；只要 PDF 时无需额外交付 HTML。

1. 从已经核验的共同内容源排版。可使用环境可用的 HTML 打印、排版引擎或 PDF 工具链；先检查依赖与字体。Linux 可检查字体清单（如 fc-list），选择实际存在且覆盖中文、拉丁文及数学符号的字体，不写死 Windows 字体路径。
2. 根据阅读设备确定字号、行宽、页尺寸与边距。手机版不照搬桌面宽布局，打印版检查灰度可读性。保留文本可搜索性；不要把全文栅格化。
3. 按契约放置答案。若从互动 HTML 打印，显式展开需要交付的解析、讲义、图与推导，并等待数学渲染完成。检查分页没有裁剪长公式、宽表和图注；只有实际生成和验证后才声称有书签或可点击目录。
4. 提取 PDF 全文并与内容源核对章节、题目、答案和重要公式；提取顺序和数学字符编码可能失真，必要时回看原页排除假缺失。
5. 渲染并查看封面/目录（如有）、中文密集页、长公式、宽表、图表、分页边界、答案及最后一页；发现问题后扩大检查范围。视觉验收包括字符、上下标、分数、括号和逻辑结构，不仅是图片像素阈值。
6. 验证文件可打开、页数合理、无空白截断与缺字；多格式任务同步内容。交付实际文件并说明验证边界。资源不足或工具受限时明确报告，不能将生成成功等同于验收通过。
